# 설치 흐름 정리
## 목적
설치를 앱 한 곳에서 끝낸다. 지금은 채팅과 앱이 서버 위치를 두 번 묻고, 설치가 두 곳에서 돌고, 앱을 끝낸 뒤 채팅에 "했어"를 쳐야 끝나서 헷갈린다("웹에서도 설치하고 에이전트도 설치하고 동시에 하는데 헷갈리거든?").
## 범위
처음 설치(Claude Code·Codex에서 시작), 설치 뒤 화면 일, 팀원 초대 문구, 앱에서 업데이트, README·AGENTS.md·설치 스킬.
## 하지 않는 것
- 플러그인 없이 시작하기(npm 패키지·Mac 앱): 훅 때문에 플러그인은 먼저 깐다(10-11). `doctor --fix`가 서버를 다시 만드는 과정의 결함(옛 소스 재사용, compose 단계 실패, 가드 토큰 공백)은 따로 고친다.
## 기능
- F1 Claude Code나 Codex에 저장소 주소와 "설치해 줘"라고 하면, 에이전트가 Node·git을 확인하고 자기에게 플러그인을 깐 뒤 앱을 열고 정해진 한 줄로 끝낸다 [사용자]
  - 케이스: Node 18 이상이나 git이 없음 → 깔아도 되는지 한 번 묻고 공식 방법으로 깐다. 사람이 설치 창을 마쳐야 하면 "끝나면 같은 말을 다시 하세요" 한 줄로 끝낸다.
  - 케이스: 이미 설치된 컴퓨터 → 다시 깔지 않고 앱의 대시보드를 연다.
- F2 `/team-memory setup`(Codex는 `$setup-memory`)은 아무것도 묻지 않고 앱을 연다. 설치 전이면 처음 설정, 설치된 컴퓨터면 같은 창의 수정이다 [사용자]
- F3 서버 위치·구독과 모델·에이전트·폴더는 처음 설정에서 한 번만 묻고, 적용이 Docker·Ollama·구독 게이트웨이 설치, 로그인, 서버 켜기, 다른 에이전트에 플러그인 넣기를 한다 [사용자]
- F4 적용의 마지막 줄은 점검이고, 끝 화면이 점검 결과와 남은 할 일(Codex 훅 승인, `/reload-plugins`)을 한 화면에 보인다. 점검에 실패한 줄마다 무엇이 안 되는지와 누를 버튼이 있어 채팅으로 돌아갈 일이 없다 [사용자]
- F5 설치 뒤의 열람 요청·팀 만들기·팀 들어가기·다른 컴퓨터의 내 서버·구독 계정 더하기도 에이전트는 그 화면을 열고 한 줄로 끝내고, 이어지는 일과 안내는 앱이 한다 [사용자]
- F6 README 첫머리는 "Claude Code나 Codex에 이렇게 말하세요"와 그 문장이고, 직접 치는 설치 명령은 그 아래에 둔다. 설치 스킬과 AGENTS.md도 이 흐름으로 고친다 [사용자]
- F7 관리자가 보낸 초대 문구 한 줄을 에이전트에 붙여 넣으면 설치부터 그 팀의 Google 로그인 화면까지 이어진다 [사용자]
  - 케이스: 이미 설치된 컴퓨터 → 다시 깔지 않고 그 팀의 로그인 단계만 연다. 이미 그 팀에 들어 있으면 팀 화면을 연다.
  - 케이스: 다른 팀에 든 컴퓨터 → 로그인 전에 "지금 팀에서 빠지고 새 팀으로 옮깁니다"를 두 팀 이름과 함께 보이고 확인을 받는다. 한 컴퓨터는 팀 하나에만 든다.
- F8 새 판이 나오면 앱이 알리고, "업데이트" 버튼 하나로 이 컴퓨터의 플러그인(Claude Code·Codex)·대화 모으기·앱·서버·게이트웨이 가운데 뒤처진 것을 새 판으로 올린다 [사용자]
  - 케이스: 서버를 다시 만드는 판(몇 분에서 10분 넘게) → 누르기 전에 그동안 팀원 열람이 멈춘다고 알리고, 진행 줄을 보인다.
## 공통 규칙
- R1 설치와 설정 중 에이전트가 하는 말은 정해진 한 줄(앱 주소 포함)과 오류뿐이고, "했어"를 기다리지 않는다 — 채팅 설명이 늘면 다시 두 곳이 된다 [AI 가정]
- R2 관리자 탭 팀 주소 줄의 "복사"는 저장소 주소와 팀 주소가 든 초대 문구를 복사한다(예: "팀 메모리 설치해 줘. https://github.com/team-memory-system/team-memory 팀 주소 team.chenjing.org") — 팀원에게 보낼 것이 늘 이 한 줄이면 된다 [AI 가정]
- R3 새 판은 앱이 하루 한 번 GitHub 공개 저장소 main의 판을 읽어 오른쪽 위 종과 대시보드 한 줄로 알리고, 저절로 올리지는 않는다 — 서버를 다시 만드는 동안 팀원 열람이 멈추니 주인이 때를 고른다 [AI 가정]
- R4 줄인 설치 스킬은 일부러 부르지 않아도 돈다. 평소 세션에서 "민준 기억 열람 요청해 줘"라고 하면 에이전트가 그 화면을 연다 — 지금은 막혀 있어(SKILL.md, openai.yaml) F5가 돌지 않는다. 화면만 여는 스킬이라 저절로 불려도 위험이 없다 [AI 가정]
- R5 끝 점검은 `doctor`의 검사에, 이 컴퓨터에 서버를 만든 설정이면 모델을 부르지 않는 기본 `server verify`를 더한다. 쌓지 않기는 팀 로그인과 팀원 서버 로그인만 본다 — 앱의 적용은 서버를 켜기만 해서, 지금은 임베딩이 안 되는 서버도 "다 됐습니다"로 끝날 수 있다 [AI 가정]

- Ruling: "이미 그 팀"은 허브 주소가 같고 로그인됐거나 로그인이 끝나 다시 기다리는 경우이고, 이때 팀 화면을 연다. 만들기만 하고 로그인하지 않았거나 로그아웃한 컴퓨터는 그 팀의 로그인 단계로 간다 — 로그인 없이 팀 화면을 쓸 수 있을 때만 보낸다 — 틀리면 같은 팀 링크가 로그인을 한 번 더 보인다 (작업 2)
- Ruling: 옮기기 확인은 로그인 단계 자리에 뜨고, 새 팀은 주소로 보인다(팀 이름은 로그인 뒤에야 안다). 버튼은 "취소"와 "옮기고 로그인"이고, 로그인 탭은 그 버튼을 누를 때 연다 — 브라우저가 클릭 없이 연 탭을 막는다 — 틀리면 문구만 바꾼다 (작업 2)
- Ruling: "옮기고 로그인"은 새 팀 로그인 전에 지금 팀에서 먼저 빠진다(`/api/team/logout`) — 다른 팀에 든 채 새 허브에 로그인하면 scripts/team-auth.mjs의 setTeam이 방금 한 로그인까지 지운다(이 작업 전부터 있던 백엔드 동작) — 틀리면 새 팀 로그인이 실패했을 때 이 컴퓨터가 어느 팀에도 없다 (작업 2)
- Ruling: 옮기기 확인은 링크와 시작 카드의 "팀에 들어가기"에 띄우고 "새 팀 만들기"에는 넣지 않았다 — F7은 들어가기 흐름이다 — 다른 팀에 든 컴퓨터에서 새 팀을 만들면 로그인 뒤 확인에서 실패한다(이 작업 전부터 있던 문제) (작업 2)
- Ruling: 설치된 컴퓨터에서 링크로 연 로그인 단계의 취소는 창을 닫는다 — 그 팀 하나 때문에 연 창이다 — 틀리면 시작 카드를 보려면 처음 설정을 다시 열어야 한다 (작업 2)
- Ruling: 주소가 어디로 가는지는 새 순수 모듈 ui/lib/landing.js가 정하고, 기억 설정의 창 고르기는 `windowOf()`로 뺐다 — 화면을 띄우지 않고 시험할 수 있게 — 잃는 것 없음 (작업 2)
- Ruling: 설치 스킬은 앞머리에서 `disable-model-invocation`만 지우고 `user-invocable: false`는 남긴다. Codex의 openai.yaml에는 `allow_implicit_invocation: true`를 적는다 — `user-invocable: false`는 `/` 메뉴에서 숨기기만 하고 모델 호출은 막지 않아, `/` 메뉴에는 `/team-memory` 하나만 남는다 — 틀리면 Claude Code에서 R4가 안 된다 (작업 1)
- Ruling: 스킬의 창 이름은 앱과 같은 기준으로 정한다. 설정 여부는 `detect`(configured, 답하는 기억 서버, 이 컴퓨터의 서버)와 `team status`(팀 로그인)로 보고, 설정 전이면 "팀 메모리 시작하기", 설정 뒤면 "대화 수집 설정"이다 — 같은 `computer/collect`가 두 창을 띄운다. 앱은 브라우저에 둔 처음 설정의 `mode`도 보지만 CLI는 못 본다 — 틀리면 로그인만 하고 처음 설정을 마치지 않은 컴퓨터에서 줄이 다른 창 이름을 말한다 (작업 1, 검토 두 번 뒤)
- Ruling: `team`·`admin`은 `team status`로, `server`·`models`·`share`는 `server status`로 먼저 본다. 팀이 없으면 `start`를 열고 "팀에 들어가기"(팀원 더하기면 "새 팀 만들기") 줄을 말하고, 관리자가 아니거나 서버가 없으면 아무것도 열지 않고 할 일 한 줄로 답한다 — 앱이 그 화면을 숨기고 대시보드를 띄우므로 — 틀리면 게이트웨이만 있는 컴퓨터(앱은 서버로 친다)에서 모델 화면을 열지 않는다 (작업 1)
- Ruling: 설치와 초대 문구는 같은 줄 "팀 메모리 앱을 열었습니다. 브라우저 창에서 이어 하세요. <url>"을 쓰고, 표에 없는 요청은 "팀 메모리 앱의 <화면 이름> 화면을 열었습니다. <url>"로 연다 — 설정 전에는 어느 화면이든 시작하기 창이 뜬다 — 틀리면 표에 없는 요청에 누를 것이 안 나온다 (작업 1)
- Ruling: SSH로 연 컴퓨터의 줄은 `ssh -o ExitOnForwardFailure=yes -L 127.0.0.1:4180:127.0.0.1:4180 <user>@<host>`이고, 포트가 차 있다고 하면 14180으로 바꾼 명령과 주소를 준다 — 묶을 주소가 없으면 ssh가 `::1`에만 묶고도 붙어 앞 컴퓨터 자신의 앱이 열린다(검토가 이 맥에서 잼). 팀 로그인의 redirect는 요청의 Host로 만들어져 다른 포트로도 된다 — 틀리면 그 경우 사람이 포트를 직접 푼다 (작업 1, 검토 두 번 뒤)
- Ruling: Node가 없거나 18보다 낮으면 오류 줄로 한 번 묻고, 그러라고 하면 README "에이전트에게" 1단계대로 깐다. Windows의 PATH는 PowerShell 형태로 적는다 — 설치 방법은 README 한 곳에 둔다 — 틀리면 Git Bash의 에이전트는 그 형태를 옮겨 써야 한다 (작업 1)
- Ruling: README의 직접 설치는 Claude Code 안에서 치는 `/plugin …`이고, 셸 명령 `claude plugin … --scope user`는 "에이전트에게" 칸에만 둔다 — 사람은 Claude Code 안에서, 에이전트는 셸에서 친다 — 잃는 것 없음 (작업 1)
- Ruling: 옛 스킬의 터미널 일은 AGENTS.md의 기존 칸을 가리키고, 그곳에 없던 것만 더한다 — 설명이 두 곳에 있지 않게 — 대조에서 빠진 게 있다면 그 내용이 문서에서 사라진다 (작업 1)
- Ruling: 설정된 컴퓨터의 "다른 컴퓨터의 내 서버"는 팀이 있어도 대화 수집 설정 창의 "서버" 단계로 보낸다. Codex 기본 프롬프트의 둘째 줄은 "Ask a teammate to open their memory to me."이고, Codex 목록의 이름과 설명은 그대로 둔다 — 그 단계에는 팀과 상관없이 그 고르기가 있다 — 틀리면 팀이 있는 사람이 "찾음" 대신 주소와 token을 직접 넣는다 (작업 1)

- Ruling: Codex만 있는 컴퓨터는 Codex 플러그인 → 앱 다시 켜기 → 대화 모으기 → 서버 차례다. 화면 파일이 없어진 옛 앱도 context의 모양으로 우리 앱으로 알아보고 갈아 끼우며, 끄기 전에 그 프로세스가 node인지 본다. 앱과 로그인 자동 시작의 작업 폴더는 앱 폴더다 — Codex 캐시는 최신 판 폴더 하나만 남겨 앱이 켜진 옛 폴더가 지워진다(검토가 찾은 심각) — 다른 프로그램을 우리 앱으로 잘못 보면 그 줄이 "Something else is answering"으로 멈춘다 (작업 4)
- Ruling: 업데이트와 고치기는 같은 잠금으로 서로를 막고, 지난 대화 쌓기(상태 파일과 pid)와 기억 다시 정리(job이 있고 error가 없으면 pid와 상관없이) 중에는 업데이트를 막는다. 다른 컴퓨터 화면에서는 업데이트의 시작과 다시 시도, 그리고 고치기(`/api/doctor/fix`)를 막는다 — 두 길이 같은 서버를 같이 다시 만들지 않게. 서버나 앱을 다시 켜는 동안 그 화면으로 오는 길이 끊기고, 끊긴 고치기를 다른 화면이 끝없이 기다렸다(작업 3 재검토). `past status`는 멈춘 실행을 다시 잇는 부작용이 있어 상태 파일만 읽는다 — 상태 파일을 쓰지 않는 긴 작업은 놓친다 (작업 4)
- Ruling: 실패의 까닭은 명령이 쓴 마지막 줄(헬스 체크면 `Honcho /health: <까닭>`)이고 앞 20줄은 접힌 detail이며, 주소는 진행 파일과 doctor --fix 출력 모두에서 가린다 — 명세의 "확인 필요": 10-17 compose 실패를 숨기지 않는다 — 긴 출력이 보일 수 있다 (작업 4)
- Ruling: 팀 허브는 올린 모듈의 이름과 내용을 합친 sha256을 기록하고(해시 없는 옛 허브는 뒤처진 것), "팀 주소 다시 올리기"는 저장된 Cloudflare token만 쓴다 — 새 token을 몰래 저장하지 않게 — 저장된 token이 없으면 관리자 탭의 token 바꾸기를 눌러야 한다 (작업 4)
- Ruling: 사람이 읽는 문구: doctor의 고칠 수 있는 실패는 "팀 메모리 앱 오른쪽 위 종에서 업데이트를 누르세요. Claude Code에서는 /team-memory doctor", 팀원의 옛 서버(0.8.0 전, 종 없음)는 "README의 업데이트 칸대로 올려 달라고 하세요" — Codex에는 `/team-memory`가 없다(R22) — 판은 다 같은데 대화 모으기나 서버만 뒤처진 경우 등에는 종에 업데이트가 안 떠서, 작업 5가 doctor의 고칠 수 있는 실패도 종에 띄운다 (작업 4, 메인 세션)

- Ruling: 다시 열면 이을 값은 앱 폴더가 아니라 브라우저의 localStorage `tm.setup`에 두고(R11의 "앱 폴더"와 다름), 적용을 누른 때부터 끝 화면까지만 둔다. token류는 담지 않고 주소는 origin과 경로만 남긴다 — 작업 3은 scripts/를 고치지 않았고, 적용 전 단계에는 token 입력이 섞인다 — 브라우저 데이터를 지우거나 다른 브라우저로 열면 처음부터 고르고, token이 필요한 원격 서버는 이어 간 뒤 점검의 "대화 수집 수정"에서 token을 다시 넣는다 (작업 3)
- Ruling: 다시 연 창(앱이 뜰 때 남은 값이 있으면 저절로 열림)은 저절로 돌지 않고 "적용 중" 목록에 끝난 줄 ✓과 "처음부터"·"이어서 하기"를 보이며, 다른 팀 링크가 오면 남은 값을 지우고 그 팀의 로그인으로 간다. 수정 창의 적용은 남은 값을 지운다. 적용 중에 창이 닫히면 돌던 줄만 끝까지 간다 — 남은 값이 나중에 바꾼 설정을 덮었다(검토) — 한 번 더 누른다 (작업 3)
- Ruling: 끝 점검의 verify는 서버가 이 컴퓨터에 있으면 새로 깔았든 이미 있었든 돈다. 점검 줄은 대화 모으기, 기억 서버, 임베딩, 대상 서버마다 한 줄, 앱(옛 판일 때만)이고, Ollama가 꺼지면 서버 줄 하나만 실패로 센다. 실패 줄도 "할 일 N개"에 센다 — 시안의 세 줄을 지키고 같은 원인을 한 번만 말하게 — 검사 하나하나는 덜 자세하다 (작업 3)
- Ruling: R10의 버튼을 넓혔다: 막힘·401·403은 "기억 서버가 이 컴퓨터의 요청을 막았습니다." 한 문장과 "대화 수집 수정", 꺼진 Claude 플러그인은 `claude plugin enable`을 담은 "명령 복사", Codex 훅·설정이 없으면 "대화 수집 수정", setup이 명령을 주지 않았으면 기본 설치 명령. 점검 줄이 명령을 가지면 같은 일을 할 일에서 뺀다 — 채팅으로 돌아갈 일이 없게, 팀원 화면에 Cloudflare 이름이 안 나오게 — 다른 marketplace에서 깐 사람에게도 기본 저장소 명령이 복사된다 (작업 3)
- Ruling: 서버를 다시 만드는 고치기는 누르기 전에 "기억 서버를 다시 만드는 동안 팀원 열람이 멈춥니다."를 보이고, 도는 동안 fix.json의 줄을 보이며, 앱이 다시 켜져 요청이 끊기면 fix.json에서 결과를 읽는다(2초 간격, 약 3분 한도). 다른 컴퓨터 화면에서는 고치기가 잠긴다 — F8 케이스와 같은 규칙 — 앱이 3분 넘게 다시 뜨지 않으면 고치기가 끝났어도 실패로 보인다 (작업 3)
- Ruling: 쌓지 않기의 점검은 팀 로그인 줄과, 로그인할 팀원 서버가 있을 때만 팀 서버 로그인 줄이다. 끝 버튼 결과(고치기·서버 켜기·로그인·명령 복사)는 토스트가 아니라 점검 칸 아래 한 줄로 보인다 — 모달 위의 토스트는 잘 안 보인다 — 없음 (작업 3)
- Ruling: 설치된 컴퓨터(설정됨, 또는 팀에서 쌓지 않기로 처음 설정을 마침)가 링크나 "팀에 들어가기"로 오면 팀 주소·로그인·팀원 단계만 걷고, 적용은 팀에 내 서버 열기·열람 요청·점검, 끝 버튼은 "팀 화면 열기"다. 허브 peer가 설정의 peer와 다를 때만 `--user-peer`만 바꾸는 "peer 이름 바꾸기" 줄을 넣는다(다른 값은 그대로 남는 것을 cli.mjs에서 확인) — F7 "다시 깔지 않고"와, setup 때 허브 peer를 받는다는 허브의 정함(hub.mjs:1235-1237) — 옛 대화와 새 대화가 두 이름으로 나뉜다(예전 전체 설정 흐름과 같음) (작업 3, 메인 세션)
- Ruling: 수정 창의 적용 끝에도 같은 점검 칸(ui/lib/check.js)을 쓰고, 이번 적용이 바꾼 에이전트(새로 고름, 훅을 새로 씀, 플러그인을 깜)의 할 일만 보인다. Codex는 훅을 새로 썼을 때만 "훅을 승인하세요"이고, 아니면 "새 세션을 여세요"다 — F4 [사용자]의 할 일을 수정에서도 보이되, 오지 않는 승인 창을 기다리게 하지 않게(검토) — 폴더만 바꾼 적용에는 할 일이 없다 (작업 3)
